Developer guide

Using seaLeye

The command line and the console do exactly the same things. Install covers the command line; for the console, open seaLeye.online in your browser and sign in.

Install

Your platform team publishes seaLeye to your internal registry, under your organization's own name. Copy and paste this line into your terminal to get seaLeye on your laptop. That's it. You're ready to run.

$ npm install -g @your-org/sealeye

Then, in your app's folder:

$ cd your-app && sealeye run

Commands

This is sealeye --help, reproduced. It carries no per-command description, so none is written here.

The command list
sealeye run [--answers <file>] [--team-context] [--watch] [--api <url>] sealeye deploy --file <plan.yaml> [--app <path>] [--api <url>] [--json] [--watch] sealeye validate --file <plan.yaml> [--api <url>] [--json] sealeye status <deploymentId> [--api <url>] [--json] sealeye watch <deploymentId> [--api <url>] sealeye destroy <app | deploymentId> [--api <url>] sealeye list [--deployments] [--all] [--api <url>] [--json] sealeye evidence <app | deploymentId> [--json] [--out <file>] [--api <url>] sealeye needs [--json] [--request <kind>] [--api <url>] sealeye doctor [--json] [--api <url>]

Options

-f, --filepath to your plan YAML
--appfolder to deploy (default: the current folder)
-b, --backendcloudformation (default: cloudformation)
--answerswith run: answer the interview from a file, one line per question, for rehearsals. Never answers "Deploy this?": that stays yours
--team-contextwith run: after a refusal, say whether another team has hit the same boundary (reads a local fixture)
--watchwith run or deploy: stay on the live panel until the deployment finishes, instead of watching in the background and notifying you
--allwith list: include environments you have torn down
--deploymentswith list: every deploy, instead of one row per environment
--outwith evidence: where to write DEPLOYMENT_EVIDENCE.md (default: the current folder)
--requestwith needs: print a module request for one need, ready to paste into a ticket. Takes the kind, or part of the need's own line
--apiplatform API base URL (default: http://localhost:3000)
--jsonmachine-readable output
-h, --helpshow help

When it says no

Not every app fits what seaLeye can build today. This one reads a stream, keeps a database connection open and must not be reachable from the internet. seaLeye never names a module it cannot build, so it does not guess at one: it says what your app needs, in plain words, with the code that shows it, and saves the plan as a draft. It also tells you when somebody else has already been here.

The change record

A bank does not ask for a URL. It asks who requested this, what they approved, what was built and whether the thing running now is still that. sealeye evidence writes it into your folder as DEPLOYMENT_EVIDENCE.md, and the console shows the same record and downloads the same file. Every value is read from seaLeye's own records and from CloudFormation at that moment, nothing is typed in, and no setting's value is ever in it.

FAQ

What is a profile?

A profile says what your plan is designed for, not where this run goes. Every run builds a dev environment. poc is a single zone, started on demand, nothing kept warm. dev is a team using it every day, with backups kept and failed work held onto. prod is data across more than one zone, capacity warm on the request path, a queue in front of anything that bursts, and alarms on errors and latency. The profile is recorded in your plan and applied by the pipeline to the environments it builds later.

What happens the second time I run it?

seaLeye tells you the app already has a live environment, shows you its URL and waits for a y before going on. If a plan is already in your folder it offers to reuse it or to start over. Start over and it looks at your app as it is now, and the card becomes a diff against what is deployed: unchanged, changed, new or removed. When nothing has moved, it says so.

What if seaLeye says it cannot build my plan?

Your plan is drafted and it is saved. seaLeye names only the modules it can build, so rather than guessing at a module for the rest, it says what your app needs and points at the code that shows it. When your organization's Platform Library has modules that support those needs, run sealeye run again and seaLeye finishes the plan.

How do I tear an environment down?

sealeye destroy <app>, with the name of the app or a deployment id. That deletes the environment and everything in it. A static site has its storage emptied first, because an environment holding files will not delete. Nothing outside that environment is touched.

What is DEPLOYMENT_EVIDENCE.md for?

For whoever asks what this environment is and how it got here: a change board, an auditor, the person who inherits it. It is the change record for one environment, written by sealeye evidence, and it holds who asked, what they answered, the checksum of the plan they approved, what was built with its checksums, the CloudFormation events from that deployment, and what AWS says about the stack right now, including whether it still runs the template that was approved and whether anything changed it outside seaLeye. Every value is read at the moment it is generated, and a value that could not be read says so rather than being guessed. It never contains a setting's value, only its name.

Where does my plan live, and can I edit it?

Two files, both written into your own folder next to your code: the plan file seaLeye runs, and a human readable version of it with every assumption spelled out. They are yours. Edit them, commit them, and deploy an edited plan directly with sealeye deploy -f. It is checked against the contract before anything is built, and a plan seaLeye finds already in your folder is offered back to you rather than overwritten.
